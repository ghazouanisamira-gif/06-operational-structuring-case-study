# Team Performance, Coaching & Capability Development

## Purpose

This workstream demonstrates a structured **people, manager and performance enablement system**: translating operational observations into capability assessments, targeted coaching, practical tools, structured routines, learning interventions, team development and measurable improvement.

The objective was not simply to deliver training. It was to **diagnose capability needs, design the right intervention, equip people with usable tools, reinforce application and develop autonomy**.

The approach covered:

### Quality / Support / Operational Contributors

- methodology and process coaching

### Production / Operational Managers

## Capability & Level Assessment

Capability development started with a **baseline assessment**, rather than assuming that every person needed the same training.

Depending on the role, the assessment could examine:

- technical knowledge
- process knowledge
- methodology
- tool proficiency
- quality standards
- communication
- problem solving
- organization and prioritization
- analytical ability
- management practices
- coaching capability
- decision-making
- stakeholder interaction
- autonomy

A practical level assessment can use a progression such as:

**Awareness → Basic Application → Operational Proficiency → Advanced Application → Autonomy / Transfer**

The assessment should identify both **strengths and development gaps** and translate them into specific development priorities.

## Development Needs Analysis

The diagnosis connected evidence from:

- level assessments
- KPI trends
- quality evaluations
- calibration results
- observation
- manager feedback
- one-to-one discussions
- operational incidents
- process deviations
- reporting quality
- employee self-assessment
- recurring questions or errors
- onboarding observations

The principle was:

**Evidence → Gap → Root Cause → Development Need → Intervention**

Not every gap was considered a training problem.

The diagnosis distinguished between:

- knowledge gap
- skill gap
- methodology gap
- tool gap
- process gap
- organization/prioritization gap
- role-clarity gap
- communication/stakeholder gap
- management-system gap
- workload/environment constraint

## Development Plan

Where a capability gap was confirmed, a structured development plan could define:

- current level
- expected level
- priority
- development objective
- intervention
- owner
- support required
- practice opportunity
- target checkpoint
- evidence of application
- reassessment method

This turns training into a **managed development cycle**, rather than an isolated event.

## Coaching Methodology

The coaching cycle was:

**Observe → Assess → Diagnose → Discuss → Demonstrate → Practice → Feedback → Apply → Follow Up → Reassess**

### Observe

Use available evidence:

- KPI trends
- quality observations
- process adherence
- dashboard signals
- customer journey drop-offs
- reporting
- feedback
- recurring operational issues

### Assess & Diagnose

Identify the real capability or operating gap and its cause.

### Coach

Adapt the intervention:

- explanation
- demonstration
- guided practice
- role play / simulation where relevant
- job aid
- checklist
- knowledge-base reference
- targeted training
- feedback conversation
- process clarification
- tool coaching
- management-routine redesign

### Follow Up

Check whether the intervention produced observable application, behavioural change, improved execution or greater autonomy.

## Debrief & Feedback System

Debriefing was used to convert experience into learning and improvement.

A structured **debrief sheet / feedback record** can capture:

- context / activity reviewed
- objective
- observations
- strengths
- gaps
- root causes
- feedback provided
- employee / manager perspective
- agreed actions
- support required
- deadline / checkpoint
- follow-up result
- next development priority

Debriefs can support:

- onboarding
- coaching
- training sessions
- quality reviews
- calibration
- post-incident learning
- manager support
- continuous improvement

The purpose is not administrative traceability alone: it is to **close the learning loop**.

## Manager Onboarding & Enablement

Manager onboarding was treated as an **operational enablement process**, not simply an information-transfer exercise.

The approach:

**Understand the role → Assess the manager → Clarify priorities → Select tools → Build routines → Coach application → Observe → Adjust → Reinforce autonomy**

Key dimensions:

| Dimension | Enablement |
|---|---|
| Role clarity | Responsibilities, interfaces, expectations and escalation |
| Operational understanding | Processes, customer journey, standards and dependencies |
| Performance management | KPIs, dashboards, review routines and actions |
| Daily organization | Priorities, recurring tasks and management checklist |
| Tools | Selection and practical adoption |
| Team management | Follow-up, feedback, coaching and escalation |
| Reporting | What, when, to whom and required analysis |
| Problem solving | RCA and corrective action |
| Capability development | Targeted training/coaching |
| Autonomy | Progressive reduction of support |

## Management Routines & To-Do Lists

**The tool must fit the role.**

Management routines could cover:

## Capability Development Model

The development model connects:

**Knowledge → Skill → Application → Consistency → Autonomy → Ability to Transfer**

The goal is not only to make someone capable of performing a task, but progressively able to **apply, explain, adapt and transfer the method**.

## Manager Enablement Principles

1. Clarify before correcting.
2. Assess before prescribing training.
3. Diagnose before coaching.
4. Adapt tools to the role.
5. Make learning practical.
6. Coach toward autonomy.
7. Use evidence whenever possible.
8. Close every intervention with follow-up.
9. Separate individual causes from systemic causes.
10. Reinforce strengths as well as gaps.
11. Standardize effective practices.
12. Transfer knowledge into the operating system.
